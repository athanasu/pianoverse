# Pianoverse app

Library and landscape player for engine `song.json` files. Design: `docs/superpowers/specs/2026-11-07-pianoverse-design.md` (§5, §6, §6.1).

## Run

Needs Node 22.22 or newer and pnpm.

```bash
pnpm install
pnpm dev
```

Open the printed URL. The demo song (`public/songs/demo`) is generated by `pnpm make:demo`.

`pnpm build` writes a static site to `dist/`. Static hosting needs an SPA fallback (serve `index.html` for unknown paths), otherwise opening or reloading `/song/:id` directly returns a 404.

## Your own songs

Run the engine (`engine/README.md`), then copy its `song.json` to `public/songs/<id>/song.json` and add an entry to `public/songs/index.json` (`id`, `title`, `key`, `bpm`, `durationSec`, `sourceType`, `chords`). Don't commit songs you don't own.

## With the backend (New song)

Adding a song (recording, choosing or dropping a file) and the processing screen need the engine's server (`engine/README.md`). Without `VITE_API_URL` the app stays the offline demo above.

The easiest way is `./dev.sh` from the repository root: it starts the server and this app together with a matching key and port. To do it by hand:

```bash
cd engine && PIANOVERSE_API_KEY=choose-a-key uv run pianoverse-server   # http://127.0.0.1:8000
cd app && cp .env.example .env.local                                      # set VITE_API_KEY=choose-a-key
pnpm dev                                                                  # open http://localhost:5173
```

| Variable | Meaning |
|---|---|
| `VITE_API_URL` | Server base URL without `/api`, e.g. `http://127.0.0.1:8000` |
| `VITE_API_KEY` | Sent as `Authorization: Bearer …`; must equal the server's `PIANOVERSE_API_KEY` |

- Open `http://localhost:5173`, not `127.0.0.1:5173`: the server's default CORS origin is `http://localhost:5173`.
- The key ends up in the web bundle: fine for a personal tool, not for a public site.
- Recording needs a secure origin: `http://localhost` counts; a LAN address over plain http does not (use the deployed https site on a phone).
- Unit tests and the demo e2e ignore `.env.local`; `pnpm test:e2e` also runs the New-song flow against a mocked API (`e2e/new-song.spec.ts`).

## Test

```bash
pnpm test      # unit + component tests
pnpm test:e2e  # demo smoke test + New song flow with a mocked API (first: pnpm exec playwright install chromium)
```

The piano sound loads from the Tone.js Salamander samples (network); without it the player keeps running silently.
